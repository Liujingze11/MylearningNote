【1.2 整体结构：Backbone → Neck → Head】
几乎所有现代目标检测器都沿用这个三阶段设计范式。

以三个类别为例子：

输入图像 (640×640×3)
       │
       ▼
┌──────────────────────────┐
│  BACKBONE（特征提取）      │   逐步压缩图像，提取多尺度视觉特征
│  层 0 ~ 9                │   分辨率越来越低，语义越来越丰富
│                          │
│  [0]  Conv              │   输入层：640×640 → 320×320，3通道→更多通道
│  [1]  Conv              │   下采样：320×320 → 160×160
│  [2]  C2f               │   特征提取块（含残差连接）
│  [3]  Conv              │   下采样：160×160 → 80×80
│  [4]  C2f               │   特征提取块
│  [5]  Conv              │   下采样：80×80 → 40×40
│  [6]  C2f               │   特征提取块
│  [7]  Conv              │   下采样：40×40 → 20×20
│  [8]  C2f               │   特征提取块
│  [9]  SPPF              │   空间金字塔池化——多感受野融合
└───────┬──────────────────┘
        │  SPPF 输出单一特征图 (20×20)，送入 Neck 做多尺度融合
        ▼
┌──────────────────────────┐
│  NECK（特征融合）          │   多尺度特征双向融合
│  层 10 ~ 21              │   语义往下传 + 细节往上传
│                          │
│  --- FPN 自顶向下：高层语义传给低层 ---                   │
│  [10] Upsample           │   P5 上采样 20×20 → 40×40
│  [11] Concat             │   拼接：上采样后的 P5 + P4
│  [12] C2f                │   融合特征
│  [13] Upsample           │   再上采样 40×40 → 80×80
│  [14] Concat             │   拼接：上采样后 + P3
│  [15] C2f                │   融合特征（小目标分支，80×80）
│                           │
│  --- PAN 自底向上：低层细节传回高层 ---                   │
│  [16] Conv               │   下采样 80×80 → 40×40
│  [17] Concat             │   拼接：下采样后 + 层12输出
│  [18] C2f                │   融合特征（中目标分支，40×40）
│                           │
│  [19] Conv               │   下采样 40×40 → 20×20
│  [20] Concat             │   拼接：下采样后 + SPPF输出
│  [21] C2f                │   融合特征（大目标分支，20×20）
└───────┬──────────────────┘
        │  输出 3 个融合特征图：P3(80×80), P4(40×40), P5(20×20)
        ▼
┌──────────────────────────┐
│  HEAD（检测输出）          │
│  层 22                   │
│                          │
│  [22] Detect             │   3 个尺度各自预测框+类别，再经 NMS 合并去重
│                          │   80×80 → 小目标 | 40×40 → 中目标 | 20×20 → 大目标
└──────────────────────────┘


【1.3 各组件详解】

  Conv（卷积层）
  - 组成：Conv2d + BatchNorm + SiLU 激活函数
  - 作用：扫描输入特征图，提取局部模式（边缘、纹理等）
  - stride=1：保持尺寸，增加通道数
  - stride=2：尺寸减半（下采样），用更少的像素表达更高级语义
    例：640×640 → Conv(stride=2) → 320×320，特征图缩小，但每个像素包含更大范围的视觉信息
  - 为什么用 SiLU（也叫 Swish）？比 ReLU 更平滑，梯度流动更稳定，对负值也有微小输出
    SiLU(x) = x · sigmoid(x)
    ReLU(x) = max(0, x)
    SiLU 在负值区域不是直接截断到 0，而是给一个很小的负值，让梯度保持流动

  C2f（Cross-Stage Partial with 2 convolutions, Fast）
  - YOLOv8 的核心创新模块，继承自 YOLOv5 的 C3 模块
  - 内部结构：
        输入
        ├──→ Conv → split 分两路
        │              ├──→ Bottleneck → Bottleneck → ...（n 个串联）
        │              └──→ 直接透传（什么都不做）
        │
        └──→ 两路在通道维度拼接 → Conv → 输出
  - "Cross-Stage Partial" = 一部分通道跳过计算直接透传
    好处：减少计算量 + 保留梯度短路路径（类似 ResNet 残差思想）
  - 为什么 backbone 里每隔一个 Conv 就放一个 C2f？
    下采样 Conv 负责压缩空间 → C2f 负责在压缩后的特征图上深入提取语义
    这是"压缩→提取→压缩→提取"的节奏
  - n（Bottleneck 数）= 该层的"深度"，nano 版 n 最小
    nano: 1-2 个 Bottleneck | small: 2-3 | medium/large: 3-4 | xlarge: 4+

  SPPF（Spatial Pyramid Pooling - Fast）
  - 位置：backbone 最后一层（第 9 层）
  - 原理：对同一特征图串行应用 3 次 5×5 MaxPool
    第 1 次 MaxPool → 感受野 = 5×5
    第 2 次 MaxPool → 感受野 ≈ 9×9（累积效果）
    第 3 次 MaxPool → 感受野 ≈ 13×13（累积效果）
    3 个输出 + 原始输入 → 拼接 → Conv
  - 为什么串行比并行快？并行需要同时维护 3 个不同池化核的中间结果；串行复用上一轮输出
  - 效果：让模型同时用小感受野看细节 + 大感受野看上下文
    就像在 20×20 图上同时用放大镜（5×5）和广角镜（13×13）看同一个区域
  - 为什么放 backbone 最后？此时特征图最小（20×20），池化计算量最小，但语义最丰富

  Upsample（上采样）
  - 使用最近邻插值将特征图尺寸放大 2 倍
  - 无学习参数，纯粹的空间分辨率恢复
  - 为什么需要？backbone 输出的 P5（20×20）语义最强但分辨率最低
    必须放大到 40×40 才能和 P4 的尺寸对齐，才能拼接

  Concat（拼接 / 串联）
  - 在通道维度上拼接两个特征图（不是对应位置相加）
  - 例：256 通道 + 256 通道 → 512 通道的特征图
  - 拼接 vs 相加：
    相加(Eltwise Add)：信息融合得直接，但可能丢失细节
    拼接(Concat)：保留两边全部信息，后面 C2f 自己决定怎么融合，更灵活

  Detect（检测头）
  - 最后一层，将特征图转换为检测输出
  - 每个特征图网格单元预测：
    - 4 个框坐标 (cx, cy, w, h)：相对于网格中心的偏移和宽高
    - 1 个 objectness 分数：该网格"有物体"的概率
    - C 个类别分数：每个类的概率
  - 3 个尺度各自预测 → NMS（非极大值抑制）合并去重 → 最终检测框
  - NMS 过程：按置信度排序 → 选最高分框 → 删掉和它重叠太多(IOU>阈值)的框 → 重复


【1.4 Neck 为什么是 "PAN-FPN" 结构】

  FPN（Feature Pyramid Network）= 自顶向下路径：
    大目标特征(P5, 20×20) → 上采样 → 传给中目标(P4, 40×40)
    融合后 → 再上采样 → 传给小目标(P3, 80×80)
    效果：高层强语义逐级传给低层分辨率 → 小目标知道"这是物体"

  PAN（Path Aggregation Network）= 自底向上路径：
    小目标特征(80×80) → 下采样 → 传给中目标(40×40)
    融合后 → 再下采样 → 传给大目标(20×20)
    效果：低层精细细节逐级传回高层 → 大目标定位更准

  合在一起 = PAN-FPN：两股信息流交汇，所有尺度共同受益

  具体映射：
    [10]↑→ [11]拼→ [12]融合  ─── FPN: P5→P4
    [13]↑→ [14]拼→ [15]融合  ─── FPN: P4→P3
    [16]↓→ [17]拼→ [18]融合  ─── PAN: P3→P4
    [19]↓→ [20]拼→ [21]融合  ─── PAN: P4→P5

  对称结构：两次上采样(FPN) ↔ 两次下采样(PAN)，一一对应


【1.5 三个尺度的检测分工 —— 以 imgsz=640 为例】

  输入 640×640 → backbone 经过 5 次下采样(stride=2) → 最终 20×20
  stride = 640 / 20 = 32（原始图像每 32×32 像素对应最后一层 1 个像素）

  尺度1：P3 = 80×80, stride=8  → 检测小目标（原图中 >8×8 像素的物体）
  尺度2：P4 = 40×40, stride=16 → 检测中目标（原图中 >16×16 像素的物体）
  尺度3：P5 = 20×20, stride=32 → 检测大目标（原图中 >32×32 像素的物体）

  同一物体在不同距离下会出现在不同尺度，三个头各司其职。


【1.6 freeze 参数与层的关系 —— 以 YOLOv8n 为例】

  freeze=N → 冻结模型参数列表中的前 N 项（层 [0] 到 [N-1]）
  冻结 = 前向传播照常计算，反向传播不计算梯度、不更新权重

  freeze=0  → 全部 23 层训练
  freeze=10 → 层[0]~[9]冻结（整个 backbone），层[10]~[22]可训（neck+head）
  freeze=22 → 只训 Detect 层，几乎不训任何东西

  常规场景选择：
  - 从头训练 / 数据充足：                      freeze=0
  - 微调（少量增量，保守）：                    freeze=10（锁 backbone）
  - 更激进但仍有保留的微调（数据差异较大）：     freeze=5（锁浅层）

【2.1 epochs（训练轮数）】

  完整遍历一轮全部训练数据 = 1 epoch，epochs=200 意味着每张训练图被模型看过 200 遍。

  如何选择 epochs：
    - 从头训练（基于预训练权重）：通常 100~300 epoch
      数据量小（~1000 张）→ 每张图需反复看才能充分学习 → 偏向 150~200
      数据量大（>10 万张）→ 每 epoch 信息量大 → 100~150 足够
      
YOLOv8n 参数量小(~3.2M)，200 epoch 是"足够又不浪费"的经验值

微调（基于已有模型）：通常 20~60 epoch，起点已在终点附近，只需修正特定场景偏差
      微调轮数 ≈ 原始训练轮数的 1/5 ~ 1/3
    - 太少（50-100）可能欠拟合，太多（300+）小数据容易过拟合

  配套调整（等比缩放）：
    当 epochs 改变时，以下参数应按比例调整：
      warmup_epochs ≈ epochs × 2%~5%
      close_mosaic  ≈ epochs × 2%~3%（保证最后几轮关掉 mosaic 精调）

  best.pt 的兜底机制：
    过拟合也不怕。训练过程中每 epoch 在验证集上评估一次：
      fitness = 0.1 × mAP@0.5:0.95 + 0.9 × mAP@0.5
    fitness 最高的那个 epoch 存为 best.pt（不是最后一个 epoch 的 last.pt）。
    所以即使 epochs 设得稍大（如 80），best.pt 会自动卡在验证集表现最好的时刻，
    额外的 epoch 只浪费 GPU 时间，不影响最终模型质量。
    这是 epochs 可以设得稍"宽松"的原因——best.pt 是安全网。


【2.2 lr0（初始学习率 / Initial Learning Rate）】

  是什么：
    学习率控制每次参数更新的步长。
      新权重 = 旧权重 - lr × 梯度
    梯度告诉你"往哪个方向走"，lr 告诉你"这一步迈多大"。
    lr 是整个训练中最重要的超参数，没有之一。

  太大：跳过最优解，loss 震荡甚至 NaN 炸掉
  刚好：平稳收敛
  太小：收敛极慢，卡在局部最优出不来

  从头训练 vs 微调的 lr 选择：
    - 从头训练（基于 COCO 预训练权重迁移到新场景）：
      COCO(~118K 图, 80 类) → 梯度方向可靠 → lr0=1e-2 大步走
      小数据(~1000 张图, 几类) → 梯度噪声大 → lr0=1e-3~5e-4 小步走
      YOLOv8n 参数量小(~3.2M)，对 lr 更敏感——同样 lr 对小模型"更猛"
    - 微调（基于已有领域模型继续优化）：
      同领域微调 → lr0 = 原始 lr × 0.1~0.2（小修小补，避免灾难性遗忘）
      跨领域迁移 → lr0 = 原始 lr × 0.3~0.5（需要更多适应空间）
      freeze 部分层时 → lr 可再降一半（可训参数少，避免集中过拟合）

  ┌─ 实战经验：如何确定 lr ─────────────────────────────────────┐
  │                                                              │
  │  方法 1：Learning Rate Finder（最科学）                       │
  │    从极小 lr(1e-8) 开始训几个 batch，每个 batch 增大 lr，     │
  │    记录 loss。loss 下降最快的区间 = 最佳 lr。                 │
  │    选最快下降点对应的 lr，再退回一个数量级（÷10）。             │
  │                                                              │
  │  方法 2：经验法则（最实用）                                    │
  │    从头训（小数据）：        1e-3 ~ 5e-4                      │
  │    从头训（大数据 COCO 级）：1e-2 ~ 5e-3                      │
  │    微调（同领域数据加量）：  原始 lr × 0.1~0.2                │
  │    微调（跨领域）：          原始 lr × 0.3~0.5                │
  │    freeze=10 微调：         比全参数微调再降一半                │
  │                                                              │
  │  方法 3：看训练曲线反推（事后验证）                             │
  │    lr 刚好：loss 平稳下降，不震荡不卡住                        │
  │    lr 太小：loss 几乎不降，跟平地一样                          │
  │    lr 太大：loss 剧烈震荡甚至 NaN                              │
  │    lr 偏大但能用：初期降得快但后期震荡不收敛                    │
  └──────────────────────────────────────────────────────────────┘


【2.3 cos_lr（余弦退火学习率调度）】

  是什么：
    决定学习率在整个训练过程中"怎么衰减"。不是阶梯式跳水，而是沿着余弦曲线平滑下降。
      lr(epoch) = lrf·lr0 + (lr0 - lrf·lr0) × (1 + cos(π × epoch/epochs)) / 2

    曲线形状：开始和结尾都平缓，中间下降速度最快。

  为什么用余弦退火而不是线性/阶梯衰减：
    - 阶梯衰减(Step)：每次衰减都是一次冲击，模型可能震荡
    - 线性衰减(Linear)：一开始就快速降速，模型还来不及充分探索
    - 余弦退火(Cosine)：
      开头保持较高 lr → 充分探索参数空间
      中间加速收敛 → 找到最优区域
      末期极低 lr → 精细打磨，等效于隐式模型平均(SWA效应)，收敛到更平坦的最优解

  注意：cos_lr 是比例衰减策略，lr 曲线形状不变，整条曲线随 lr0 等比上下移动。
  无论从头训练还是微调，cos_lr 本身始终启用，只需要调整 lr0 和 lrf。

  一句话：cos_lr 是现代 YOLO 训练的事实标准，设为 True 就行，不需要因场景改变而调整。


【2.4 lrf（最终学习率因子 / Learning Rate Factor）】

  是什么：
    决定学习率衰减的终点。最终 lr = lr0 × lrf。
    lrf 控制的是"尾巴有多长"——lrf 越小，尾巴越长，末期 lr 越趋近于零。

    例（以 lr0=5e-4 为参考）：
      lrf=0.01 → 终点=5e-6（几乎归零，YOLOv8 默认）
      lrf=0.1  → 终点=5e-5（还比较活跃）
      lrf=0.5  → 终点=2.5e-4（只衰减一半）

  为什么 YOLOv8 默认 lrf=0.01：
    - 末期 lr 趋近于零，最后十几个 epoch 模型在"原地打磨"
    - 等效于隐式模型平均（SWA），有助于收敛到平坦最优解，泛化更好
    - 太小（0.001）→ 末期完全学不动，浪费最后几个 epoch
    - 太大（0.1）  → 末期仍有更新幅度，收敛不够彻底

  什么时候该调 lrf：
    - 从头训练：保持 lrf=0.01，让末期充分收敛
    - 精调场景：可适当提高到 0.05~0.1，让末期保持一定学习能力
    - lrf 是比例系数，自动跟随 lr0 等比缩放，通常只需调 lr0


【2.5 warmup_epochs（学习率预热）】

  是什么：
    训练最开始的 N 个 epoch 里，学习率不从 lr0 起步，而是从 0 线性爬升到 lr0。
    相当于"热身"，给模型一个缓冲期。

      epoch 0  → lr ≈ 0（几乎不动）
      epoch 1  → lr ≈ lr0 / 2
      epoch 2  → lr = lr0（正式进入训练）

  为什么需要预热：
    - 模型初始化时权重是随机的，梯度方向不可靠
    - 如果一开始就用全速 lr，不可靠的梯度 × 大 lr → 参数被冲飞
    - 预热让模型先用小步幅"探路"，梯度稳定后再全速前进
    - 对于小数据集尤其重要：batch 间梯度波动大，预热能平滑初始阶段的噪声

  经验公式：warmup = 总 epochs 的 2%~5%，一般取 3%~5%。
    例：epochs=200 → warmup=3~5
        epochs=100 → warmup=2~3
        epochs=60  → warmup=2

    太少（1 epoch）：预热不充分，初始不稳定
    太多（>10 epoch）：浪费计算，且预热期 lr 低，学不到什么东西


【2.6 batch（批大小）】

  是什么：
    GPU 一次同时处理多少张图片算梯度、更新一次权重。
    batch=16 = 每一步拿 16 张图 → 算这 16 张的平均梯度 → 更新模型。

  三条线决定 batch 取值：

  线 1——显存硬约束：
    batch ↑ → 显存 ↑ → OOM
    batch ↓ → 显存 ↓ → 训练变慢（每个 epoch 更多 step）
    YOLOv8n + imgsz=640 + 单卡，16 是常见舒适值

  线 2——BatchNorm 统计质量：
    YOLO 每层 Conv 后都有 BatchNorm，BN 在 batch 内算均值和方差做归一化
    batch=2-4  → BN 统计噪声大，训练震荡
    batch=8    → 勉强可用
    batch=16   → 统计稳定，梯度方向可靠
    batch=32   → 更好但显存放不下

  线 3——泛化（大 batch 困境）：
    batch 太小 → 梯度噪声大 → 隐式正则化 → 泛化好，但慢
    batch 太大 → 梯度平滑 → 收敛快但易陷入尖锐最优 → 泛化差
    16 在速度和泛化之间取平衡，保留适度梯度噪声

  注意：freeze 只减少反向传播的计算，前向传播照样跑全部层，显存几乎不降。
  同模型、同显卡、同 imgsz 时，batch 不需要因 freeze 而调整。


【2.7 imgsz（输入图像尺寸）】

  是什么：
    所有输入图片被 resize 到这个尺寸，再喂给模型。
    不管原图是 1920×1080 还是 800×600，一律压成 640×640 正方形。

  为什么是 640：
    - YOLOv8 官方推荐尺寸，预训练权重都基于 640
    - 5 次 stride=2 下采样后得到 20×20 特征图，stride=32
    - P3(80×80, stride=8)  → 可检测原图中 ≥8×8 像素的目标
    - P5(20×20, stride=32) → 可检测原图中 ≥32×32 像素的目标

  为什么不用 1280：
    imgsz 翻倍 → 显存 ×4（640²→1280²）→ 速度 ÷4。
    对小物体检测有帮助，但需要权衡性价比。

  为什么不用 320：
    imgsz 减半 → 显存 ÷4，但小目标会模糊，容易漏检增加。

  注意：改变 imgsz 会导致预训练权重的尺度不匹配，更换 imgsz 意味着需要更多训练
  让模型适应新分辨率。一旦选定，保持稳定。


【2.8 mosaic（马赛克数据增强）】

  是什么：
    随机抽 4 张图，分别放到左上、右上、左下、右下，拼成一张 640×640 的新图。
    标签也跟着平移。拼接边界上被截断的标签自动丢弃。

  为什么用：
    - 场景多样性爆炸：同一物体出现在不同背景/位置/邻近物体旁，学到"本质特征"
    - 天然小目标：4 张挤进 1 张 → 每个物体相对缩小 → 提升小目标检测
    - 数据量等效放大：4 选 1 组合远大于原图数量

  副作用：
    - 拼接图统计分布 ≠ 真实单图统计分布（train-test 偏移）
    - 拼接边界的标签被丢弃，部分标注浪费
    - 工业固定相机场景（背景统一、物体尺寸稳定），拼接多样性的价值不如自然图像

  什么时候该关掉：
    - 固定场景、背景统一、物体完整清晰（如工业相机拍摄）
    - 拼接破坏了目标完整性，边界的标签又浪费掉
    - 增量数据量少，落在边界上反而学不到
    - 场景要求检测完整物体，不需要识别半截的

  注意：关闭 mosaic 时 close_mosaic 也应设为 0（无 mosaic 可关）。


【2.9 close_mosaic（最后 N 轮关闭 mosaic）】

  是什么：
    mosaic 开启时，最后 close_mosaic 个 epoch 关掉它，用原始单图训练。
    目的是纠正全程 mosaic 带来的 train-test 分布偏移。

  经验公式（按总 epochs 等比缩放）：
    总 epochs=300 → close_mosaic=10  (YOLOv8 官方默认)
    总 epochs=200 → close_mosaic≈5~7
    总 epochs=100 → close_mosaic≈3~5
    即 close_mosaic ≈ 总 epochs 的 2%~3%

  如果 mosaic=0，close_mosaic 无意义，直接设为 0。


【2.10 mixup（混合增强）】

  是什么：
    两张图按随机比例做像素加权叠加，标签也按同样比例融合。
      新图 = α×图A + (1-α)×图B    （α 从 Beta 分布采样）
    相当于"制造"了两类之间的过渡样本。

  为什么用：
    - 软化分类边界：让模型在类别之间看到渐变，减少过拟合
    - 对类别混淆场景（同环境下不同物体外观接近）有效

  副作用：
    - 混合后的图像不逼真——推理时不会出现这种"叠加"场景
    - 过度使用会引入噪声，模型学到的是假象

  什么时候适合关掉：
    - 类别外观差异明显、边界本身就清晰
    - 固定场景下混合增强的价值低于自然图像
    - 需要修正边界混淆时——靠真实标注修正，而不是靠 mixup 模糊边界
    - 关掉后模型只看到真实图像，不会学到半张A半张B的"幽灵样本"


【2.11 multi_scale（多尺度训练）】

  是什么：
    每 step 有 50% 概率随机改变整张图片的输入分辨率（320~960），而不是固定 640×640。
    解决的是"推理时图片分辨率可能变化"的泛化问题。

  与 scale（几何增强）的区别：
    scale：图里物体放大/缩小，背景不变
    multi_scale：整张图分辨率变化，物体和背景等比缩放

  什么时候适合关掉：
    - 固定相机场景，部署和训练时分辨率一致，不需要分辨率泛化
    - 关掉后输入尺寸始终固定，训练更稳定


【2.12 HSV 色彩增强：hsv_h、hsv_s、hsv_v】

  是什么：
    在 HSV 色彩空间随机扰动图像，模拟不同光照条件。HSV 比 RGB 更贴近人感知颜色的方式。

    H（Hue/色相）：什么颜色。0~360°色环。
    S（Saturation/饱和度）：颜色浓淡。0=灰白，1=最鲜艳。
    V（Value/明度）：亮度。0=全黑，1=最亮。

    hsv_h=0.015 → 色相最多偏移 1.5%（红色不会变绿色）
    hsv_s=0.7  → 饱和度最多变化 70%（鲜艳↔灰白）
    hsv_v=0.4  → 亮度最多变化 40%（过曝↔偏暗）

  为什么 H 极小、S/V 较大：
    - H 几乎不动：工业场景颜色是功能标识（红急停/绿启动），颜色语义不能乱
    - S 大幅变：模拟设备新旧差异（新设备鲜艳、旧设备褪色）
    - V 中等幅变：模拟光照差异（直射光、阴影、夜间）
    → "保留颜色语义，只增减光照差异"——一个很聪明的设置

  注意：HSV 增强不改变物体形状/完整性，只影响颜色——不会引入假样本。
  Hard case 可能就是某种光照条件下触发的——HSV 增强让模型在更多光照变体上见过类似场景。
  是一种相对安全、适用范围广的增强方式，几乎不需要因场景改变而调整。


【2.13 几何增强：degrees / translate / scale / shear / perspective / flipud / fliplr】

  7 个参数控制对图像的几何变换：

  ┌─ 通常关闭的 4 个 ──────────────────────────────────────────────┐
  │ degrees=0.0   旋转：固定朝向场景（工业面板、PCB 等）旋转会破坏语义。 │
  │               需要旋转不变性的场景（航拍、自然图像）可适度开启。     │
  │ flipud=0.0    上下翻转：天花板不会是地板，绝大多数场景永远关。      │
  │ shear=0.0     剪切：模拟侧向拍摄造成的梯形变形。极小幅(2°)         │
  │               无伤大雅，但"能不开就不开"原则下维持关闭。          │
  │ perspective=0 透视：模拟俯仰/倾斜视角。最容易产生扭曲，          │
  │               且视角变化靠 backbone 特征泛化就能扛。            │
  └──────────────────────────────────────────────────────────────┘

  ┌─ 通常开启的 3 个 ──────────────────────────────────────────────┐
  │ fliplr=0.5    左右翻转(50%)：左右对称场景的合法增强。            │
  │ scale=0.5     缩放(0.5~1.5倍)：模拟不同拍摄距离，最有价值的     │
  │               几何增强。                                       │
  │ translate=0.1 平移(±10%)：模拟相机微小偏移和物体位置变化。       │
  └──────────────────────────────────────────────────────────────┘

  几何增强策略跟数据量无关，只跟拍摄条件有关。场景物理特性不变，
  增强策略就不需要变。


【2.14 copy_paste（复制粘贴增强）】

  是什么：
    从一张图随机截取实例，粘贴到另一张图上。用于实例分割任务。

  为什么检测任务通常为 0：
    检测任务关注的是框的回归（定位+分类），不是分割边界的精度。
    copy_paste 对分割的实例边界学习有帮助，对检测意义不大。始终关闭。

【3.1 核心训练参数】

| 参数 | 常用范围 | 说明 | 调参指南 |
|------|:------:|------|----------|
| **epochs** | 100-300 | 遍历全部数据的次数 | 从头训练 100-150；微调 20-50。观察 mAP95 和 Val Loss 是否趋于平台 |
| **imgsz** | 320-1280 | 输入图片尺寸 | 越大细节越多，但显存翻倍。640 是性价比最优值 |
| **batch** | 8-128 | 每步处理几张图 | 受显存限制。6GB 显卡跑 seg 模型建议 8-16。batch 越大梯度越稳定 |
| **device** | 0/cpu | GPU 编号 | 自动检测，单卡填 0，多卡填 [0,1] |

💡 经验

epochs 不是越大越好 →
例如：
   e100: mAP95=0.8397
   e150: mAP95=0.8477（峰值在 ep131，之后过拟合）
   → 有效提升集中在 100-130 轮，后面 20 轮是浪费的


【3.2 学习率三件套 ⭐（最重要的三个参数）】

| 参数 | 常用范围 | 说明 |
|------|:------:|------|
| **lr0** | 0.01→0.0001 | 初始学习率。**从头训练 0.01，迁移学习 0.001，精调 0.0003-0.0005** |
| **lrf** | 0.01-0.1 | 最终 lr 系数。`最终lr = lr0 × lrf`。精调时建议 0.1（衰减更平缓） |
| **warmup_epochs** | 0-5 | 前 N 轮 lr 从极小逐步升到 lr0，防止开局方向跑偏 |

lr 衰减曲线：

lr0=0.001, lrf=0.01（YOLO 默认，适合从头训练）:
  0.001 ┤╲
        ┤ ╲________余弦衰减
  0.00001┤  ╲_____________
         └─────────────────

lr0=0.0005, lrf=0.1（精调策略）:
  0.0005 ┤        ╲
         ┤   ╱      ╲___
  0.00005┤──╱              ╲
         └──────────────────
         0  warmup3   10  25

🎯 甜区发现（实战数据）

e150 实验 ep100-130 期间的实际 lr 与 mAP95 增量：
  lr=0.00027 → mAP95=0.834（ep100）
  lr=0.00022 → mAP95=0.841（ep110）
  lr=0.00017 → mAP95=0.844（ep120）
  lr=0.00011 → mAP95=0.847（ep130）★峰值

结论：有效精调 lr 区间 = 0.00005 ~ 0.0003
     低于 0.00005 模型几乎不更新，白跑
     高于 0.0005 步子太大，会破坏已学特征

lr 选择速查表：

| 场景 | 推荐 lr0 | 推荐 lrf | epochs |
|------|:------:|:------:|:------:|
| 从头训练 | 0.01 | 0.01 | 100-300 |
| 迁移学习（预训练权重） | 0.001 | 0.01 | 50-150 |
| 精调（已有不错权重） | 0.0003-0.0005 | 0.1 | 20-50 |
| 极精细调优 | 0.0001 | 0.2 | 10-30 |


【3.3 防止过拟合】

| 参数 | 常用范围 | 说明 |
|------|:------:|------|
| **close_mosaic** | 5-15 | 最后 N 轮关闭 Mosaic 增强，让模型适应单张真实图。设 0 = 全程不关 |

过拟合诊断速查：

看 results.png 第一张子图（train/box_loss vs val/box_loss）：

  ✅ 正常:  Train ↓   Val ↓  → 两条线一起降
  ⚠️ 过拟合: Train ↓   Val ↑  → 蓝降红升，模型在死记训练集
  ℹ️ 平台期: Train →   Val →  → 都不动，考虑调 lr 或加数据

再看第三行 mAP50-95：
  持续上升 → 模型还在进步
  开始下降 → 过拟合确认，该停了

4. 数据驱动模型优化方法论
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【4.0 前言】

核心思想只有一句话：模型的上限由数据决定，算法的上限由迭代效率决定。


【4.1 高效标注策略 —— 滚动式半自动标注】

适用场景：
任何需要大量人工标注的监督学习项目（分类、检测、分割、OCR、关键点等）。

核心思想：
> 不要让标注成为训练的瓶颈。先用少量高质量数据训出一个"可用"的模型，再用它加速后续标注。

通用流程：

第 1 轮：手动标注打底（~20-30% 数据）
    ↓
第 2 轮：训练一个"够用就行"的模型
    ↓
第 3 轮：模型自动预标注剩余数据
    ↓
第 4 轮：人工修正（比从零标注省 60-70% 时间）
    ↓
第 5 轮：合并数据，重新训练，模型更强
    ↓
循环至全部数据标注完毕


关键原则：

| 原则 | 说明 |
|------|------|
| 第一批数据质量至上 | 第一批手动标注数据决定了后续自动标注的准确度上限，必须覆盖全类别、全场景、全变化模式 |
| 每轮自动标注量适中 | 每次 100-200 条，保证修正不成为新的瓶颈 |
| 模型越强，修正越少 | 第 2 轮可能需大量修正，第 4 轮可能只需微调 |
| 修正后立即训练 | 高质量标注立刻转化为模型能力，让下一轮自动标注更准 |
| 不要等到数据"完美"再开始训练 | 有一个可用的基础模型比追求标注完美更重要 |

为什么有效：
这是一个正反馈循环：更好的数据 → 更好的模型 → 更好的自动标注 → 更好的数据。每一次循环都在加速下一次循环。


【4.2 数据分布与领域迁移 —— 最核心的经验】

问题本质：
> 模型只会学习它见过的东西。训练数据和实际使用场景之间的任何分布差异，都会直接转化为模型在实际场景中的失败。

常见表现：
- 模型在验证集上指标很好，但实际使用中某些场景完全失效
- 某些子类/子场景的准确率远低于平均水平
- 模型对特定变化（尺度、角度、光照、背景）极其敏感

根本原因：
训练数据中某些场景（尺度/角度/光照/类别/背景）的样本量不足，导致模型将该场景视为"噪声"而忽略。

核心原则：
> 少数群体（长尾场景）的样本量不能低于多数群体的 1/2，否则其特征会被淹没。

这不是一个精确的数学定理，而是一个工程经验法则：
- 比例 1:3 以上 → 少数群体几乎学不到
- 比例 1:2 → 少数群体开始能学到，但不稳定
- 比例 1:1 → 各类群体均衡学习

通用解决方案：

1. 分析训练数据的分布（按场景/尺度/角度/类别等维度）
      ↓
2. 识别长尾群体（样本量远低于中位数的子集）
      ↓
3. 针对性补充长尾群体数据，拉近比例
      ↓
4. 重新训练/微调，验证长尾群体指标是否提升


关键洞察：
> 数据不平衡导致的模型失败，无法通过调参解决。必须补数据。

数据增强（过采样、SMOTE、mosaic、mixup 等）只能缓解数据不平衡，不能根治。如果某个子场景完全缺失或严重不足，增强手段也无能为力。


【4.3 模型迭代策略 —— 何时重训、何时微调】

核心决策：
模型迭代时，面临一个关键选择：从原始预训练权重重新训练，还是从现有最佳模型继续微调？

决策框架：

数据变化量 > 30%？
    ├── 是 → 从原始预训练权重重新训练
    │        （数据分布发生了本质变化，需要重新学习）
    │
    └── 否 → 数据变化量 > 10%？
              ├── 是 → 从当前最佳模型微调
              │        （在已有知识基础上温和补充新知识）
              │
              └── 否 → 从当前最佳模型微调，用更低的学习率
                       （小量修正，防止破坏已有能力）


经验法则：

| 数据增量 | 策略 | 原因 |
|:--:|------|------|
| >30% | 从原始权重重训 | 数据分布已显著改变，续训容易陷入局部最优 |
| 10%-30% | 从最佳模型微调，lr 降一半 | 在现有知识基础上温和扩展 |
| <10% | 从最佳模型微调，lr 再降一半 | 精细修正，最小化对已有能力的干扰 |

反模式：错误的重训策略

踩过的坑：数据增量 15% 时，从中间模型续训 + 极低 lr → 某些类别性能退化。

为什么会退化：
- 续训起点不合适：模型已经在某个局部最优，小 lr 无法跳出
- 新数据量与 lr 不匹配：增量不算小，但 lr 过低导致新知识学不进去，反而干扰了旧知识
- 经验法则：增量 >15% 且有数据分布变化时，从原始权重重训更安全

核心原则：
> 与其在错误的起点上调参，不如从正确的起点重新开始。


【4.4 学习率（lr）调度经验】

通用参考：

| 场景 | 推荐 lr（相对基础 lr） | 说明 |
|------|:--:|------|
| 从预训练权重全新训练（大数据集 >1000 条） | 1×（如 0.01） | 正常起步 |
| 从预训练权重全新训练（小数据集 300-500 条） | 0.5×（如 0.005） | 小数据集需要更温和的学习 |
| 从自己的模型微调，增量 10-30% | 0.05×（如 0.0005） | 保护已有知识 |
| 少量补数据，增量 <10% | 0.02×（如 0.0002） | 精细调整 |
| 数据增量很小但有难例需要学习 | 0.05× + 更多 epochs | 给模型时间消化难例 |

核心原则：
> lr 的大小决定了"新知识"和"旧知识"的权衡。lr 越小，越倾向于保留旧知识；lr 越大，越倾向于学习新知识（但可能遗忘旧知识）。

实践建议：
- lr 不是越小越好：太小会导致新知识学不进去，浪费算力
- lr 不是越大越好：太大会破坏已有能力，造成"灾难性遗忘"
- 当不确定时，做对照实验：同一个数据，用两个不同 lr 各跑一轮，看哪个效果更好


【4.5 训练轮次（Epochs）经验】

通用参考：
轮次没有绝对标准，以下是根据数据量的经验范围：

| 数据规模 | 推荐 epochs 范围 | 说明 |
|------|:--:|------|
| 300-500 条 | 80-100 | 小数据集需要更多轮来充分学习 |
| 500-1000 条 | 60-80 | 中等规模 |
| 1000-5000 条 | 40-60 | 数据充足，每轮信息量大 |
| 微调（增量 <30%） | 30-40 | 不需要从头学，在已有基础上微调 |

核心原则：
> 数据越少，需要的 epochs 越多（每轮信息量少，需要更多轮来收敛）；数据越多，需要的 epochs 越少（每轮信息量大，更快收敛）。

实践建议：
- 配合早停（Early Stopping）使用，不要死板固定轮次
- 微调时宁可少跑几轮，过拟合的风险比欠拟合更大


【4.6 解决类别/场景混淆的通用方法】

问题表现：
- A 类经常被误识别为 B 类
- 两个相似类别之间混淆严重
- 数据增强（翻转、颜色扰动、mixup 等）无法有效改善

根本原因：
模型从未或很少见过 A 和 B 同时出现的场景，因此没有学到它们的区分性特征。

唯一有效的解决方案：
> 补拍/补采两个易混淆类别同框（同时出现）的数据。让模型在同一个画面中看到它们的差异，迫使模型学习区分性特征。

为什么数据增强无效：
- 翻转/旋转/颜色扰动：不改变类别间的相对关系
- Mixup/Mosaic：随机拼接无法保证易混淆类别出现在同一画面
- 过采样：只是重复已有样本，不提供新的区分信息

所需数据量：
通常 15-30 个高质量的"同框"样本就能显著改善混淆问题——因为每个同框样本都同时包含了正例和易混淆负例，信息密度极高。


【4.7 验证集设计与评估策略】

常见错误：
> 验证集和训练集同分布 → 验证指标虚高，不能反映真实场景表现。

正确的验证集设计原则：

1. 验证集必须覆盖所有目标场景
   - 如果实际使用有近景和远景，val 里必须有近景和远景
   - 如果实际使用有白天和夜晚，val 里必须有白天和夜晚

2. 分开评估，而不是只看一个总数字
   - 总 mAP 可能看起来不错，但某个子场景可能已经崩溃
   - 按场景维度拆分评估，确保每个子场景都达标

3. 验证集不要参与训练集的数据增强流程
   - Val 数据保持原始分布，反映真实世界的样貌

核心原则：
> 如果你不评估它，你就不会优化它。验证集的设计决定了你优化了什么。


【4.8 指标选择 —— 不要追错数字】

常见陷阱：
盲目追求某个"标准"指标，而忽略了它在你具体场景中的含义。

通用原则：

| 指标 | 什么时候重要 | 什么时候不重要 |
|------|------|------|
| mAP / Accuracy（宽松阈值，如 IoU=0.5） | 部署场景对位置精度要求不高 | 需要精确定位的场景 |
| mAP / Accuracy（严格阈值，如 IoU=0.75+） | 需要精确定位的场景 | 小目标场景（IoU 天然偏低） |
| Recall（召回率） | 漏检代价高（安全、医疗等） | 误检代价远高于漏检 |
| Precision（精确率） | 误检代价高（用户体验敏感） | 漏检代价远高于误检 |
| mAP50-95 或类似综合指标 | 单一尺度/场景的数据集 | 多尺度/多场景混合的数据集 |

核心洞察：
> 在多场景混合数据集中，"严格"的综合指标（如 mAP50-95）天然偏低，因为小目标/远场景的物理分辨率限制了上限。这种低指标不代表模型有问题，而是场景本身的物理瓶颈。以实际使用感受为准。

实践建议：
- 主指标：选一个与你业务目标最对齐的指标作为主优化目标
- 辅助指标：用其他指标监控，防止顾此失彼
- 最终评判：实际场景测试的感受 > 任何数字指标


【4.9 完整迭代闭环（科学方法）】

万能流程：

┌─────────────────────────────────────────┐
│                                         │
│  1. 部署实测（让模型面对真实世界）        │
│           ↓                             │
│  2. 定位问题                            │
│     - 哪个类/场景出问题？                │
│     - 漏检还是误检？                     │
│     - 特定尺度/角度/光照？               │
│           ↓                             │
│  3. 针对性补数据                         │
│     - 漏检 → 补该场景的多角度/多尺度数据   │
│     - 混淆 → 补同框数据                  │
│     - 每类 20-40 条通常足够              │
│           ↓                             │
│  4. 微调（从最佳模型出发，降低 lr）        │
│           ↓                             │
│  5. 验证 → 确认问题是否解决              │
│     │                                   │
│     └──── 回到步骤 1 ────────────────┘   │
│                                         │
└─────────────────────────────────────────┘

为什么这个流程有效：
> 不是"猜测模型哪里不好然后乱补数据"，而是观察 → 诊断 → 干预 → 验证的科学方法。每一次循环都是有针对性的，而不是盲目的。


【4.10 核心理念总结】

十条黄金法则：

1. 数据决定上限：模型架构和算法只能逼近数据的信息上限，不能超越。花时间优化数据比调参收益大得多。

2. 不要等到数据"完美"再开始：先训练一个可用模型，用它来加速后续工作（标注、分析、筛选）。

3. 分布差异 = 性能损失：训练数据和实际场景的任何分布差异，都是你需要付出的性能代价。要么接受，要么补数据。

4. 长尾群体不能低于 1/2：少数群体的数据量至少达到多数群体的一半，否则模型学不会。

5. 混淆靠同框数据解决：数据增强不能替代真实的多类别同场景数据。

6. lr 是"新旧知识"权衡器：学习率越小越保守（保留旧知识），越大越激进（拥抱新知识）。

7. 验证集是优化目标的代理：你验证什么，模型就优化什么。验证集设计错了，整个优化方向就错了。

8. 不要追单一指标：选择与业务对齐的主指标，用辅助指标防偏，以实际感受为最终法官。

9. 迭代走闭环，不走直线：每次迭代都是"观察→诊断→干预→验证"的完整循环，不是一次性工作。

10. 从正确的起点开始：数据发生本质变化时，回到原始权重重训比从错误起点续训更安全、更省时间。


【4.11 附录：快速诊断清单】

当模型效果不达预期时，按以下顺序排查：

□ 1. 训练数据是否覆盖了目标场景？（分布分析）
□ 2. 各类/各场景数据量是否均衡？（长尾检查，比例 ≥ 1:2）
□ 3. 验证集是否真实反映部署场景？（验证集设计）
□ 4. 所选指标是否与业务目标对齐？（指标选择）
□ 5. 学习率是否合适？（lr 诊断）
□ 6. 是否存在类别混淆且缺少同框数据？（混淆诊断）
□ 7. 是否需要从头重训而非微调？（策略诊断）


> 一句话总结：好的模型不是训出来的，是迭代出来的。每一次迭代都在数据、策略和评估中积累经验，最终让模型逼近数据的信息上限。

5. 训练实战典型案例
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【5.1 半自动标注流水线 —— 操作详解】

问题：分割/检测标注（画多边形/框）极其耗时。如果一次把所有图片都手动标注完再训练，效率太低。

解决方案：滚动式半自动标注

手动标注少量数据 → 训练基础模型 → 用工具自动预标注新数据
        ↑                                                                                                           ↓
    └──── 再训练，如此循环 ←── 手动修正自动标注结果 ←──┘


具体操作步骤：

第 1 轮：手动打底
- 手动标注首批数据（建议 200-400 张），覆盖所有类别、尽可能多的角度和距离
- 关键：第一批数据质量要高，这决定了模型后续自动标注的准确度

第 2 步：训练第一个可用模型
- 用这批数据训练一个基础模型（epochs 可稍多，如 80-100）
- 这个模型不需要完美，只要大概能检测/分割到目标即可

第 3 步：工具自动预标注
- 用训练好的模型，在标注工具中对新增的未标注数据自动推理
- 模型会自动生成初步的标注结果（检测框或分割多边形）

第 4 步：手动修正
- 逐张检查自动标注结果
- 修正：拖拽顶点/框边界、删除错误标注、补标漏掉的目标
- 修正比从零标注快得多（大约节省 60-70% 时间）

第 5 步：合并训练，滚动循环
- 修正后的数据 + 原有数据 → 新的数据集
- 再训练 → 模型能力增强 → 自动标注更准
- 再用更强模型标注下一批数据 → 修正量越来越少
- 循环直到所有数据标注完毕

经验总结：

| 要点 | 说明 |
|------|------|
| 第一批手动标注要扎实 | 覆盖全类别、全场景，这是地基 |
| 每轮自动标注量不要太大 | 每次 100-200 张，避免修正成为瓶颈 |
| 模型越强，修正越少 | 第 2 轮修正量大，第 4 轮可能只需微调 |
| 不要一次标注全部数据 | 先训一个可用模型，让它帮你标注剩下的 |
| 修正完后立刻训练 | 新标注立刻转化为模型能力，下一轮更准 |


【5.2 典型案例：数据分布失衡的诊断与修复】

案例一：单一场景训练 → 其他场景完全失效

现象：
模型在训练场景（如近距离拍摄）上指标极高，但切换到另一场景（如远距离拍摄）
时完全检测不到目标。

原因：
训练数据全部来自单一场景，模型从未见过其他尺度/角度的目标，将其视为背景。

教训：
> 训练数据必须覆盖所有目标部署场景。单一场景训练出来的"高分模型"只在
> 该场景内有效，跨场景可能完全不可用。


案例二：数据比例失衡 → 双向退化

现象：
新增少量目标场景数据（如远景数据只占总量 ~15%）后继续训练，结果：
- 新场景没学会（数据太少，特征被淹没）
- 原场景能力反而退化（新数据的梯度干扰了已学权重）
→ "双输"局面：两边都没顾好。

原因：
- 少数群体样本量太低（比例 > 1:3），模型将其视为噪声
- 学习率对微调场景偏大，破坏了原有权重

关键数据：
- 比例 1:5.5 → 少数群体完全学不会，且干扰多数群体
- 比例 1:1.6 → 多数群体指标恢复，少数群体开始学到
- 比例 1:1  → 最理想，但通常不现实
- 底线：比例 ≥ 1:2

教训：
> 数据比例至少 1:2（少数:多数），低于这个比例少数群体学不会。
> 比例严重失衡时，降 lr 也救不回来——必须补数据。


案例三：均衡数据后指标回升

现象：
追加少数群体数据、拉近比例后，从同一基础模型重新训练：
- 主要指标（如 mAP50）恢复到接近纯原场景的水平
- 综合严格指标（如 mAP50-95）仍低于纯原场景模型

原因：
- 多场景混合数据集中，小目标/远场景的物理分辨率限制了严格指标的上限
- 这不是模型有问题，而是场景本身的物理瓶颈

教训：
> 比例拉近后，宽松阈值指标能追平。严格指标的差距可能是物理瓶颈，
> 不要追这个数字——以实际使用感受为准。


【5.3 典型案例：类别混淆的诊断与修复】

问题现象：
- 某些类别在特定场景下检测不到
- 两个外观相似的类别频繁互相误识别
- 数据增强（mosaic、翻转、颜色扰动等）无法改善

问题定位方法：
1. 在实际部署环境中测试，收集失败案例
2. 逐类分析：哪个类、什么场景（距离/角度/光照）、漏检还是混淆？
3. 判断是"数据不足"还是"类别混淆"

针对性解决：

漏检（某类特定场景检测不到）：
→ 补充该类在目标场景下的多角度、多距离数据（每类 20-40 张通常足够）

混淆（A类 ↔ B类）：
→ 补充两个类同时出现在同一画面中的数据（同框数据，15-30 张通常有效）
→ 原因：模型需要同时看到两个易混淆类别，才能学到区分性特征

为什么数据增强无法解决混淆：
- 翻转/旋转：不改变类别间的相对关系
- Mosaic/Mixup：随机拼接无法保证混淆类别出现在同一画面
- 过采样：只是重复已有样本，不提供新的区分信息

核心洞察：
> 混淆的唯一可靠解法是补同框数据。让模型在同一画面中对比两个类别的差异，
> 迫使它学到区分性特征。数据增强只是锦上添花，不能替代真实数据。


【5.4 指标选择的陷阱：mAP50-95 在多尺度数据中的"虚低"】

现象：
模型在多尺度混合数据集（同时包含近景和远景目标）上训练后：
- mAP50 指标正常（如 0.95+）
- mAP50-95 指标明显低于纯单一场景训练的模型
- 但实际使用体验并没有变差

原因：
mAP50-95 是 IoU 从 0.5 到 0.95（步长 0.05）的 10 个阈值下的平均精度：
- 远景目标在图像中面积小（可能仅 20×30 像素）
- 小目标对像素级偏差极其敏感——预测框偏 2 像素，IoU 就剧烈下降
- 这不是模型定位能力差，而是物理分辨率的上限

结论：
> 在混合尺度数据集中，mAP50-95 天然偏低。不要盲目追求这个数字。
> 对于小目标/远场景，mAP50 更能反映真实检测能力。

实践指南：

| 数据集特征 | 推荐主指标 | 原因 |
|------|------|------|
| 单一尺度（目标大小一致） | mAP50-95 | 能区分定位精度 |
| 多尺度混合（大小目标混杂） | mAP50 | 不受物理分辨率干扰 |
| 安全敏感场景（漏检代价高） | Recall | 宁可多检不可漏检 |
| 用户体验敏感（误检代价高） | Precision | 宁可漏检不可误检 |

最终准则：实际部署场景的测试感受 > 任何数字指标。


【5.5 核心实战原则七条】

1. 数据比例
   > 少数组（如远景/小目标/特定场景）不能低于多数组的 1/2，否则会被淹没。

2. 微调起点
   > 始终从已训练的最佳模型出发微调，不要回到基础模型从头训。
   > 每次微调相当于在已有知识上补充新知识。

3. 学习率选择

   | 场景 | lr |
   |------|:--:|
   | 从预训练权重训新任务（数据 >1000 张） | 0.01 |
   | 从自己训的模型继续微调（增量 ≤30%） | 0.0005 |
   | 少量补数据（增量 ≤10%） | 0.0002 |

4. 训练轮次

   | 数据量 | epochs |
   |------|:--:|
   | 300-500 张 | 80-100 |
   | 500-800 张 | 60-80 |
   | 追加微调（增量 <30%） | 30-40 |

5. 解决混淆的唯一方法
   > 补拍两个类同框的数据。数据增强（mosaic, mixup）只能部分缓解，不能根治。

6. 验证集的设计
   > val 里必须同时包含所有目标场景，且按场景维度分开评估。
   > 否则总指标掩盖子场景崩溃，失去参考意义。

7. 不要追错指标
   > 混合尺度数据集上，mAP50-95 天然偏低（小目标对 IoU 敏感）。
   > 以 mAP50 为主、实际部署测试感受为准。


【5.6 训练履历记录模板】

每次训练迭代都应记录以下信息，形成可追溯的优化脉络：

| 版本 | 数据组成 | 关键比例 | epochs | lr | 主指标 | 发现的问题 |
|------|------|:--:|:--:|:--:|:--:|------|
| v1 | 场景A（基础数据） | — | 100 | 0.01 | ★基线 | 场景B完全失效 |
| v2 | v1 + 场景B(少量) | 比例失衡 | 50 | 0.001 | ↓↓ | 双向退化，比例不足 |
| v3 | v1 + 场景B(追加) | 比例拉近 | 80 | 0.0005 | ★恢复 | 某类远场景弱、某两类混淆 |
| v4 | v3 + 针对性补图 | 均衡 | 30 | 0.0002 | 待验证 | 待测试 |

使用建议：
- 每行记录一次完整的训练迭代
- "发现的问题"一栏是下一轮数据采集的指南
- 关注指标的变化趋势，而非绝对值
- 配合实际部署测试结果，标注哪些问题已解决、哪些仍存在
